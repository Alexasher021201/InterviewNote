## 1. 先记住这句话

**BM25 是一种基于词项匹配的文档相关性评分算法，综合词频、词的稀有程度和文档长度，并对词频采用饱和处理。**

在 RAG 中，它可以给候选资料打分、排序，供后续模型参考。它不依赖 Embedding 模型，本身也不生成答案。

```text
用户提问 → 分词与查询处理 → 倒排索引查找候选
         → BM25 评分与排序 → 取回原文片段 → LLM 生成答案
```

## 2. 三个核心因素

| 因素 | 统计什么 | 如何理解 |
|---|---|---|
| TF：词频 | 查询词在当前文档中出现几次 | 在其他条件固定时，出现更多通常贡献更高，但收益递减 |
| IDF：逆文档频率 | 整个集合中有多少篇文档包含该词 | 越少见的词，通常越能区分文档 |
| 长度归一化 | 当前文档长度相对平均长度的比例 | 在命中次数等条件相同时，短文档通常得分更高 |

直觉：短篇《退款规则》里出现“退款”，通常比一本长手册偶然出现一次更集中；但把“退款”重复 100 次，也不会获得一次命中的 100 倍分数。

“词稀有”只表示在当前语料中更有区分力，不表示这个词对应的内容一定更真实、更新或更权威。

## 3. BM25 与倒排索引是什么关系？

**倒排索引是数据结构，BM25 是评分方法。**全文检索系统可以先用倒排索引定位包含查询词的文档，再利用词频、文档长度等信息评分。[全文检索官方说明](https://www.elastic.co/docs/solutions/search/full-text/how-full-text-works)

例如：

```text
“退款” → D1：出现2次；D2：出现1次
“申请” → D1：出现1次
“会员” → D3：出现1次
```

查询“退款”时，系统可以直接访问对应列表。生产引擎还有候选剪枝等优化，不等于每次遍历全部文档逐字匹配。

中文一般先做分词等分析；文档和查询的分析策略需要兼容。这里说的长度是词项数量，包含重复项，不是汉字数。

## 4. 公式与符号

下面采用一种常见的 BM25 形式，查询中每个不同词项各累计一次贡献，不额外计入查询词频权重。

$$
\operatorname{BM25}(q,D)=\sum_{t\in q}\operatorname{IDF}(t)\frac{f(t,D)(k_1+1)}{f(t,D)+k_1\left(1-b+b\frac{|D|}{\operatorname{avgdl}}\right)}
$$

纯文本对照：

```text
BM25(q,D) = 对查询词 t 的贡献求和

单个词的贡献 = IDF(t) × [f(t,D) × (k1+1)]
               / [f(t,D) + k1 × (1-b + b×文档长度/平均文档长度)]
```

| 符号 | 含义 |
|---|---|
| q | 分析后的查询词项集合 |
| D、t | 当前文档、当前查询词项 |
| f(t,D) | 词项 t 在 D 中出现的次数 |
| 文档长度 | D 分词后的词项数量，重复出现也计数 |
| avgdl | 被检索文档集合的平均长度 |
| k1 | 控制词频饱和程度 |
| b | 控制长度归一化程度 |

IDF 采用下面这种常见的非负形式：

$$
\operatorname{IDF}(t)=\ln\left(1+\frac{N-n(t)+0.5}{n(t)+0.5}\right)
$$

纯文本对照：`IDF(t) = ln(1 + (N-n(t)+0.5)/(n(t)+0.5))`。

- N：参与统计的文档数。本例假设所有文档都有被检索的字段。
- n(t)：包含 t 的文档数，不是 t 在所有文档中的出现次数总和。
- ln：自然对数。
- 0.5：公式中的平滑项，避免直接使用未经平滑的比例。

IDF 有不同写法，不能混用不同版本的公式和计算结果。本例与 Lucene 文档中的这类 IDF 形式一致。[Lucene IDF 说明](https://lucene.apache.org/core/7_6_0/core/org/apache/lucene/search/similarities/BM25Similarity.html)

## 5. 完整手算：搜索“退款”

### 5.1 数据与参数

假设知识库只有以下三篇文档，直接给出分词后的结果：

| 文档 | 词项序列 | 长度 | “退款”词频 |
|---|---|---:|---:|
| D1 | 退款 / 申请 / 退款 / 进度 | 4 | 2 |
| D2 | 退款 / 规则 | 2 | 1 |
| D3 | 会员 / 积分 / 兑换 / 商品 / 使用 / 说明 | 6 | 0 |

查询：`退款`。取 k1 = 1.2，b = 0.75。

### 5.2 第一步：平均文档长度

$$
\operatorname{avgdl}=\frac{4+2+6}{3}=4
$$

纯文本：`平均长度 = (4+2+6)/3 = 4`。

### 5.3 第二步：“退款”的 IDF

N = 3，n(退款) = 2。虽然“退款”总共出现 3 次，但包含它的文档只有 2 篇。

$$
\operatorname{IDF}(\text{退款})=\ln\left(1+\frac{3-2+0.5}{2+0.5}\right)=\ln(1.6)\approx0.470
$$

纯文本：`IDF(退款) = ln(1 + 1.5/2.5) = ln(1.6) ≈ 0.470`。

### 5.4 第三步：分别算分

D1：词频为 2，长度为 4。

$$
S(D_1)=0.470\times\frac{2\times2.2}{2+1.2(0.25+0.75\times4/4)}=0.470\times\frac{4.4}{3.2}\approx0.646
$$

D2：词频为 1，长度为 2。

$$
S(D_2)=0.470\times\frac{1\times2.2}{1+1.2(0.25+0.75\times2/4)}=0.470\times\frac{2.2}{1.75}\approx0.591
$$

D3：词频为 0，贡献为 0，通常不会进入这个词的命中结果。

```text
D1 = 0.470 × 4.4 / 3.2  ≈ 0.646
D2 = 0.470 × 2.2 / 1.75 ≈ 0.591
D3 = 0

排序：D1 > D2 > D3
```

计算时建议使用未四舍五入的 IDF，最后统一保留小数；这里为展示清晰，代入式显示为 0.470。

### 5.5 这个结果说明什么？

D1 的“退款”词频是 D2 的两倍，得分却只略高，原因包括词频饱和与 D2 更短。

不能据此推断所有文档的词频翻倍都只增加这个比例；最终得分同时受长度、词频、IDF 和参数影响。

### 5.6 多词查询怎么算？

如果查询是 `退款 申请`，分别计算两个词对每篇文档的贡献，再相加：

```text
IDF(申请) = ln(1 + (3-1+0.5)/(1+0.5)) ≈ 0.980829

D1 中“申请”词频为1，长度等于平均长度：贡献 ≈ 0.980829
D1 总分 ≈ 0.646255 + 0.980829 ≈ 1.627084
D2 只有“退款”贡献：总分 ≈ 0.590862
D3 两个词都不包含：总分 = 0
```

BM25 评分与“必须命中全部查询词”是两回事。搜索系统中的 AND、OR、短语查询等控制匹配条件；通过条件筛选后，再进行相关性评分。

## 6. 参数怎么理解？

### 6.1 k1：控制词频饱和

在文档长度和其他条件固定时：

- k1 较小：词频更快饱和，第二、第三次出现带来的额外收益较小。
- k1 较大：重复出现对排序的影响通常更强，饱和更慢。
- k1 = 0：对已命中的词项，词频部分退化为 1，只保留 IDF 贡献；未命中仍贡献 0。

理解饱和时，应在同一长度条件下比较，而不是把长度也改变后只归因于词频。

### 6.2 b：控制长度归一化

- b = 0：不考虑文档长度。
- b = 1：使用完整的相对长度归一化。
- 在 0 到 1 的范围内增大 b，会增强长短文档的相对影响；不表示所有文档的得分都降低。

Elasticsearch 的 BM25 默认参数为 k1 = 1.2、b = 0.75；这只是一个具体系统的默认配置，不是所有任务的最优值。[参数官方文档](https://www.elastic.co/docs/reference/elasticsearch/index-settings/similarity)

**调优建议：**先检查数据、分词、字段、切分和查询匹配，再基于标注集调整参数，避免用参数掩盖数据问题。

## 7. 在 RAG 中怎么用？

### 7.1 和向量检索互补

| 情况 | BM25 的价值 | 需要注意 |
|---|---|---|
| 错误码 ERR_1042、型号 AX-731 | 利用明确词项进行定位 | 分词器可能拆开符号，需要设计合适的字段或精确查询 |
| 专有名词、产品名称 | 保留显式术语匹配信号 | 新词词典与查询分析影响结果 |
| 口语问题与文档用词不同 | 可配合同义词或查询扩展 | 基础公式本身不提供语义理解 |
| “允许退款”与“不允许退款” | 能找到包含相关词的资料 | BM25 本身不能可靠解释否定、条件与政策优先级 |

“BM25 擅长精确术语”不代表它自动等同于数据库精确匹配。订单号等字段若要求完全一致，应使用精确字段 / 过滤或业务查询。

### 7.2 典型混合检索流程

```text
                  ┌→ BM25 召回 ───┐
用户问题 ─────────┤               ├→ 融合去重 → 可选 Reranker
                  └→ 向量召回 ────┘              → 原文证据 → LLM
```

BM25 分数与余弦相似度通常不在同一尺度，不能未经处理就相加。可以采用按排名融合的 RRF，或经过验证的归一化 / 加权方案。[微软 RRF 说明](https://learn.microsoft.com/en-us/azure/search/hybrid-search-ranking)

Reranker 对已召回的候选重新排序；如果必要资料没有进入候选集，通常无法靠重排找回。

### 7.3 文档切分也会改变 BM25

如果把每个 chunk 当成一条索引文档，N、n(t)、词频、平均长度都按 chunk 集合统计。切分策略改变，不仅影响上下文完整性，也会改变分数。

重叠切分可能复制词项与证据，要注意候选去重。保留标题、条款条件、来源、版本和权限，不能只保存检索分数。

## 8. 常见误区与排查方法

### 8.1 不能这样理解

| 错误说法 | 正确理解 |
|---|---|
| BM25 就是关键词出现次数 | 还考虑稀有程度、长度和词频饱和 |
| TF 和 DF 都是在数词 | TF 数一篇内出现次数，DF 数包含该词的文档数 |
| BM25 分数 0.8 表示 80% 正确 | 它是相关性排序信号，不是正确率或概率 |
| 所有查询都可用一个固定阈值 | 分数受查询、语料、字段和实现影响，应按任务验证 |
| 分数高说明内容更新、更权威 | 版本、时效和权威性需额外处理 |
| 关键词检索完全不能处理同义词 | 搜索系统可添加同义词、扩展等；基础 BM25 依赖词项匹配 |
| 切块后与整篇文档分数一样 | 索引统计粒度改变，通常会改变评分 |
| k1、b 调好就能解决所有漏检 | 解析、分词、查询条件和索引同步可能才是原因 |

### 8.2 原文有答案，BM25 却找不到，怎么查？

建议按下面顺序排查：

1. **数据是否存在：**文档是否解析成功、是否进入目标索引，更新是否生效？
2. **词项是否一致：**检查查询与文档分析后的结果，尤其是中文新词、型号、标点和大小写。
3. **是否被条件排除：**租户、权限、版本、日期、字段及 AND 条件是否正确？
4. **是否有命中但排名低：**检查词频、IDF、长度、字段权重以及 Top-K 截断。
5. **是否排序之后被丢弃：**检查融合、去重、重排和上下文组装。

对于 Elasticsearch，可用分析与评分解释工具检查实际词项和评分贡献。实际引擎可能有字段统计、分片统计、长度近似和常数简化，不能要求引擎分数与本文手算逐位一致。[分析 API](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-indices-analyze)、[Explain API](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-explain)

评估时先建相关文档标注集，观察 Recall@K、MRR 或 nDCG，再看端到端回答效果与延迟。调参集与最终测试集分开；没有答案的问题单独评估，不能只靠 BM25 分数判断。

## 9. 最小 Python 复现

以下代码只用 Python 标准库，可复现本文的单词和多词计算。输入已经分词；它是教学用全量计算，不是生产倒排索引实现。

```python
from collections import Counter
from math import log

docs = [
    ["退款", "申请", "退款", "进度"],
    ["退款", "规则"],
    ["会员", "积分", "兑换", "商品", "使用", "说明"],
]
counts = [Counter(doc) for doc in docs]
N = len(docs)
avgdl = sum(map(len, docs)) / N
k1, b = 1.2, 0.75

def bm25(query, doc_index):
    score = 0.0
    length = len(docs[doc_index])
    for term in dict.fromkeys(query):  # 每个不同查询词计算一次
        tf = counts[doc_index][term]
        if tf == 0:
            continue
        df = sum(term in terms for terms in counts)
        idf = log(1 + (N - df + 0.5) / (df + 0.5))
        denominator = tf + k1 * (1 - b + b * length / avgdl)
        score += idf * tf * (k1 + 1) / denominator
    return score

for query in [["退款"], ["退款", "申请"]]:
    print("查询：", " ".join(query))
    for i in range(N):
        print(f"D{i+1}: {bm25(query, i):.6f}")
```

预期输出：

```text
查询： 退款
D1: 0.646255
D2: 0.590862
D3: 0.000000
查询： 退款 申请
D1: 1.627084
D2: 0.590862
D3: 0.000000
```

## 10. 高频面试题与参考回答

**Q1：BM25 是什么？**

基于词项匹配的文档相关性评分算法，综合 TF、IDF 和长度归一化，词频贡献采用饱和处理。

**Q2：它和 TF-IDF 有什么区别？**

两者都利用词频与稀有程度。相较于常见的简单 TF×IDF 打分，BM25 显式引入可调的词频饱和和相对文档长度归一化。TF-IDF 本身也有多种变体，不能说所有 TF-IDF 都不考虑长度。

**Q3：为什么词频增加时得分不线性增加？**

因为重复出现的额外相关性证据会递减。固定长度时，公式中词频同时出现在分子和分母，带来饱和效果。

**Q4：为什么短文档可能得分更高？**

同样命中一次，短文档通常主题更集中。BM25 按相对平均长度修正，但不是无条件偏向所有短文档。

**Q5：中文分词重要吗？**

重要。倒排索引中的词项和查询词项匹配不上，就可能没有候选；应检查新词、同义表达及型号等特殊格式。

**Q6：为什么还要向量检索？**

用户和文档可能使用不同措辞，向量检索提供语义信号；BM25 提供显式术语信号，是否混合由业务评估决定。

**Q7：换一批文档，原文没变，分数会变吗？**

可能。N、DF、平均长度等语料统计可能改变。分数不是脱离语料独立存在的绝对相关性。

**Q8：BM25 能理解“不允许退款”吗？**

它能利用词项匹配检索资料，但基础评分本身不能可靠完成否定理解和规则判断，仍需结合证据与业务逻辑。

**Q9：知识库有权限限制，如何处理？**

通过可信身份和检索 / 读取链路的授权检查约束可用资料，在原文进入 LLM 上下文前完成权限校验，不能靠提示词替代授权。

**Q10：用一句话讲它在 RAG 中的作用。**

BM25 是词项召回与排序的一种基础方法，可与向量召回融合，再经重排选出证据供 LLM 回答。

## 11. 自测题与速记

### 自测题

2. 若 b = 0，D1、D2 的得分分别是多少？
3. 若 k1 = 0，本例中包含“退款”的 D1、D2 是否同分？
4. 查询改成“退款 申请”，为什么“申请”的 IDF 更高？
5. 如果查询词完全未出现在索引词项里，调大 k1 能解决吗？

### 参考答案

1. n(t) 是文档频率，统计包含该词的文档数。
2. D1 约 0.646255，D2 约 0.470004；D1 恰好等于平均长度，所以得分不变。
3. 同分，约 0.470004；这里对命中词项词频部分为 1，未命中仍为 0。
4. “申请”只在一篇文档中出现，在当前语料中更稀有。
5. 不能凭空产生词项命中，应检查分词、扩展、同义词或考虑语义检索。

**30 秒回答：**

> BM25 是一种基于词项匹配的文档相关性评分算法。它综合查询词在文档中的频率、该词在语料中的稀有程度，以及文档相对平均长度，并用词频饱和避免重复词线性增加得分。实现中通常通过倒排索引快速找到候选。在 RAG 里，它适合保留术语、型号等词项匹配信号，可以和向量检索融合，再通过重排选择证据。实际效果依赖分词、字段、切块和语料统计，分数不能当作答案正确率。
