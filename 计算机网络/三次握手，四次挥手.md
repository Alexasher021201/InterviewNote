可以。TCP 的**三次握手**和**四次挥手**是计算机网络面试和考试的绝对高频题。你复习时不要只背“发了什么包”，重点理解：**为什么建立连接要 3 次，关闭连接通常要 4 次。**

## 一、先建立整体概念

TCP 是**面向连接、可靠传输**的协议。

两台机器真正传输数据之前，需要先确认：

> “我能给你发，你能收到；你能给我发，我也能收到。”

这个过程就是 **TCP 三次握手（Three-way Handshake）**。

通信结束之后，双方还需要分别确认：

> “我的数据发完了，我准备关闭发送方向。”

这个过程就是 **TCP 四次挥手（Four-way Handshake）**。

---

# 二、TCP 三次握手

假设：

- Client：客户端
- Server：服务器

最经典的过程：

```text
Client                                  Server
  |                                       |
  | -------- SYN=1, seq=x --------------> |
  |                                       |
  | <--- SYN=1, ACK=1, seq=y, ack=x+1 --- |
  |                                       |
  | -------- ACK=1, ack=y+1 ------------> |
  |                                       |
  |          连接建立成功                   |
```

可以简单记成：

```text
客户端：我要连接你
服务器：好的，我收到；我也准备好了
客户端：好的，我知道你准备好了
```

## 第一次握手：Client → Server

客户端发送：

```text
SYN = 1
seq = x
```

SYN 是 **Synchronize**，表示请求建立连接。

例如：

```text
Client -> Server

SYN = 1
seq = 100
```

客户端发送完成后进入：

```text
SYN_SENT
```

服务器收到这个包之后至少知道：

> 客户端 → 服务器，这个方向是通的。

---

## 第二次握手：Server → Client

服务器回复：

```text
SYN = 1
ACK = 1

seq = y
ack = x + 1
```

例如：

```text
Server -> Client

SYN = 1
ACK = 1

seq = 500
ack = 101
```

这里有两个含义：

```text
ACK：
我收到了你的 SYN

SYN：
我也希望与你建立连接
```

所以第二次握手其实把 **SYN + ACK** 合并在一个 TCP 报文里。

服务器此时进入：

```text
SYN_RCVD
```

客户端收到后知道：

> 我发给服务器的数据能到；服务器发给我的数据也能到。

---

## 第三次握手：Client → Server

客户端再回复服务器：

```text
ACK = 1
ack = y + 1
```

例如：

```text
Client -> Server

ACK = 1
ack = 501
```

客户端进入：

```text
ESTABLISHED
```

服务器收到 ACK 后也进入：

```text
ESTABLISHED
```

此时 TCP 连接正式建立。

---

# 三、为什么一定要三次握手？

这是面试非常喜欢问的问题：

> **为什么 TCP 不能两次握手？**

关键是：

**两次握手不足以让服务器确认“服务器 → 客户端”的通信能力正常。**

我们看一下。

第一次：

```text
Client ------ SYN ------> Server
```

Server 知道：

```text
Client -> Server 正常
```

第二次：

```text
Client <--- SYN + ACK --- Server
```

Client 收到以后知道：

```text
Client -> Server 正常
Server -> Client 正常
```

但是问题来了：

**Server 并不知道自己的 SYN 是否真的被 Client 收到了。**

所以 Client 必须再回复：

```text
Client ------ ACK ------> Server
```

Server 收到之后才确认：

```text
Server -> Client 正常
```

因此可以这么背：

```text
第一次握手：
Server 确认 Client -> Server 正常

第二次握手：
Client 确认 Client -> Server 和 Server -> Client 正常

第三次握手：
Server 确认 Server -> Client 正常
```

最终：

> **三次握手使通信双方都能够确认自己的发送能力和接收能力正常，同时同步双方的初始序列号。**

这句话很适合作为面试标准答案。

# 四、TCP 四次挥手

TCP 连接建立以后，双方都可以发送数据：

```text
Client <================> Server
```

现在假设 **Client 主动关闭连接**。

过程：

```text
Client                                   Server
   |                                        |
   | -------- FIN ------------------------> |
   |                                        |
   | <------- ACK ------------------------- |
   |                                        |
   |       Server 可能继续发送剩余数据        |
   |                                        |
   | <------- FIN ------------------------- |
   |                                        |
   | -------- ACK ------------------------> |
   |                                        |
   |             连接关闭                    |
```

简单记：

```text
Client：我数据发完了，我不发了
Server：好的，我知道了

Server：我数据也发完了，我也不发了
Client：好的，我知道了
```

---

# 五、四次挥手详细过程

## 第一次挥手：Client → Server

Client：

```text
FIN = 1
```

意思是：

> 我的数据发送完了，我以后不再发送数据。

注意！

**FIN 不代表 Client 不能接收数据。**

TCP 是**全双工通信**，两个方向可以独立关闭：

```text
Client ------> Server

Client <------ Server
```

Client 关闭：

```text
Client ------X Server
```

不代表：

```text
Client <------ Server
```

也关闭了。

所以 Client 仍然可以继续接收 Server 的数据。

---

# 六、第二次挥手：Server → Client

Server 收到 FIN 后回复：

```text
ACK
```

意思：

> 我知道你不再发送数据了。

但是 Server 自己可能还有数据没发完。

例如：

```text
Client：

“我请求已经发送完了。”

Server：

“好的，但我的响应还有 10MB 没发送完。”
```

所以这时候：

```text
Client ----X----> Server

Client <--------- Server
                 继续发送数据
```

这就是为什么：

> **收到 FIN 后不能直接把连接完全关闭。**

---

# 七、第三次挥手：Server → Client

等 Server 数据全部发送完：

```text
Server ---- FIN ----> Client
```

意思：

> 我的数据也全部发完了，我也准备关闭发送方向。

---

# 八、第四次挥手：Client → Server

Client 收到 FIN 后：

```text
Client ---- ACK ----> Server
```

意思：

> 好的，我知道你也不发了。

至此双方的发送方向都关闭：

```text
Client ----X----> Server

Client <---X----- Server
```

连接最终关闭。

---

# 九、为什么三次握手，四次挥手？

这是最重要的理解点。

你可能会问：

> 建立连接的时候 SYN + ACK 可以合并，为什么关闭的时候 FIN + ACK 不一定合并？

因为建立连接时，Server 收到 SYN：

```text
Client：

我要建立连接

Server：

我同意 + 我也建立连接
```

这两个操作通常可以同时完成：

```text
SYN + ACK
```

所以：

```text
1 SYN
2 SYN + ACK
3 ACK
```

一共三次。

---

但关闭连接的时候不同。

Client：

```text
我不发了
FIN
```

Server：

```text
好的，我知道了
ACK
```

**但 Server 自己可能还有数据没有发送完。**

所以不能马上发送 FIN。

等 Server 数据发送完：

```text
Server：

我也不发了
FIN
```

Client：

```text
好的
ACK
```

因此：

```text
1 FIN
2 ACK

   ↓ Server继续发送剩余数据

3 FIN
4 ACK
```

这就是经典四次挥手。

所以面试可以回答：

> **TCP 是全双工协议，两个方向需要分别关闭。主动关闭方发送 FIN 后，只代表它不再发送数据；被动关闭方收到 FIN 后先回复 ACK，但它可能仍有数据需要发送，因此 FIN 和 ACK 通常不能像三次握手中的 SYN 和 ACK 一样立即合并，所以通常需要四次挥手。**

注意这里最好说**“通常四次”**，因为在某些情况下 ACK 和 FIN 确实可能合并。

# 十、一个特别重要的状态：TIME_WAIT

四次挥手还有一道超级高频面试题。

主动关闭的一方最后发送 ACK 后，并不会马上彻底消失，而会进入：

```text
TIME_WAIT
```

并等待：

```text
2MSL
```

之后才真正 CLOSED。

所以：

```text
Client                           Server

FIN -------------------------->

    <--------------------- ACK

    <--------------------- FIN

ACK -------------------------->

↓
TIME_WAIT

等待 2MSL

↓

CLOSED
```

---

# 十一、为什么需要 TIME_WAIT？

主要记两个原因。

### 原因 1：保证最后一个 ACK 能到达

假设 Client 最后的 ACK 丢失：

```text
Client ---- ACK --X--> Server
```

Server 没收到，就会想：

> Client 是不是没收到我的 FIN？

于是 Server 会**重新发送 FIN**：

```text
Server ---- FIN ----> Client
```

如果 Client 已经彻底销毁连接，就没办法正常处理。

有 TIME_WAIT：

```text
Client：
我还在 TIME_WAIT，收到你的 FIN 了。

Client ---- ACK ----> Server
```

这样可以保证连接可靠关闭。

### 原因 2：让旧连接中的报文在网络中消失

网络中可能还残留旧 TCP 连接的数据包。

等待 `2MSL` 可以降低旧连接报文干扰后续相同四元组连接的风险。

---

# 十二、MSL 是什么？

MSL：

```text
Maximum Segment Lifetime
```

即：

> **TCP 报文段在网络中的最大生存时间。**

所以：

```text
TIME_WAIT = 2 × MSL
```

你复习时知道这个概念即可。

---

# 十三、状态变化建议记住

考试和面试经常出现 TCP 状态。

### 三次握手

```text
Client                         Server

CLOSED                         LISTEN
  |                              |
  | ---- SYN ------------------> |
  |                              |
SYN_SENT                      SYN_RCVD
  |                              |
  | <-- SYN + ACK -------------- |
  |                              |
  | ---- ACK ------------------> |
  |                              |
ESTABLISHED                  ESTABLISHED
```

最重要的：

```text
LISTEN
SYN_SENT
SYN_RCVD
ESTABLISHED
```

### 四次挥手

主动关闭方：

```text
ESTABLISHED
     ↓
FIN_WAIT_1
     ↓
FIN_WAIT_2
     ↓
TIME_WAIT
     ↓
CLOSED
```

被动关闭方：

```text
ESTABLISHED
     ↓
CLOSE_WAIT
     ↓
LAST_ACK
     ↓
CLOSED
```

尤其记：

```text
主动关闭方 → TIME_WAIT

被动关闭方 → CLOSE_WAIT
```

这两个在后端排查网络问题时也非常常见。

# 十四、面试背诵版

如果面试官问：

**“介绍一下 TCP 三次握手。”**

你可以直接回答：

> TCP 建立连接需要三次握手。第一次客户端发送 SYN 和初始序列号，请求建立连接；第二次服务器收到后返回 SYN+ACK，确认客户端请求并发送自己的初始序列号；第三次客户端再发送 ACK 确认服务器的 SYN。三次握手完成后双方进入 ESTABLISHED 状态。三次握手的核心目的是让双方确认双向通信能力正常，并同步初始序列号。

如果问：

**“介绍一下 TCP 四次挥手。”**

可以回答：

> TCP 关闭连接通常需要四次挥手。主动关闭方首先发送 FIN，被动关闭方收到后回复 ACK。由于 TCP 是全双工协议，此时被动关闭方可能还有数据需要发送，所以不能立即关闭；等数据发送完成后再发送 FIN，主动关闭方收到后回复 ACK。主动关闭方随后进入 TIME_WAIT，等待 2MSL 后关闭连接。
