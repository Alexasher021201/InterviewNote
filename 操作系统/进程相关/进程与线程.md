# 1. 什么叫「资源分配」？

你运行一个程序时，操作系统需要给它提供各种东西，比如：

- 内存空间
- 文件描述符
- 网络连接/socket
- 代码段、数据段、堆
- 各种系统资源

这些东西主要是以**进程**为单位进行管理的。

比如你打开：

```text
Chrome
IDEA
微信
```

操作系统可以认为有不同的进程：

```text
操作系统
│
├── Chrome 进程
│     ├── 自己的内存
│     ├── 打开的文件
│     └── 网络连接
│
├── IDEA 进程
│     ├── 自己的内存
│     └── 打开的文件
│
└── 微信进程
      ├── 自己的内存
      └── 网络连接
```

Chrome 一般不能随便访问微信进程的内存。

所以所谓：

> **进程是资源分配的基本单位**

可以先粗略理解为：

> 操作系统创建进程的时候，会给这个进程准备一套独立的运行资源，尤其是**独立的虚拟地址空间**。

# 2. 什么叫「调度」？

调度说的是另一个问题：

> **CPU 下一秒到底让谁运行？**

假设你的电脑 CPU 现在有一个核心，但是同时有：

```text
线程 A
线程 B
线程 C
线程 D
```

大家都想使用 CPU。

但一个 CPU 核心在某一个瞬间通常只能执行一个线程。

于是操作系统就需要决定：

```text
0~10ms     → 运行线程 A
10~20ms    → 运行线程 B
20~30ms    → 运行线程 C
30~40ms    → 又运行线程 A
...
```

这个决定：

> 谁运行、什么时候运行、运行多久

就叫做**调度（Scheduling）**。

而现代操作系统实际调度执行的基本实体通常是**线程**。

所以：

> **线程是 CPU 调度的基本单位。**

# 3. 为什么资源给进程，但 CPU 调度线程？

这才是这句八股真正需要理解的地方。

比如你启动 IDEA。

可以有一个 IDEA 进程：

```text
IDEA 进程
│
├── 线程1：负责 UI
├── 线程2：负责代码分析
├── 线程3：负责文件读取
└── 线程4：负责其他后台任务
```

这些线程属于**同一个进程**。

因此它们可以共享这个进程拥有的很多资源：

```text
               IDEA 进程
        ┌────────────────────┐
        │      代码段         │
        │      堆内存         │ ← 线程共享
        │      打开的文件      │
        │      其他资源        │
        └────────────────────┘
           ↑      ↑      ↑
         线程A   线程B   线程C
```

但是 CPU 执行的时候，不会简单地说：

> “我要运行 IDEA 进程。”

更准确地说，是：

> “我要运行 IDEA 进程里面的某一个可运行线程。”

例如：

```text
CPU Core 0 → 线程 A
CPU Core 1 → 线程 B
CPU Core 2 → Chrome 的线程 C
CPU Core 3 → 微信的线程 D
```

因此：

```text
资源归谁管理？
     ↓
    进程

CPU 现在执行谁？
     ↓
    线程
```

# 4. 一个很形象的类比

可以把**进程想象成公司，线程想象成员工**。

公司拥有：

```text
办公室
电脑
文件
数据库
资金
```

相当于：

```text
进程拥有：
内存
文件
网络资源
……
```

这些属于公司的资源。

而真正干活的是：

```text
员工 A
员工 B
员工 C
```

相当于：

```text
线程 A
线程 B
线程 C
```

所以：

> **进程负责“拥有资源”，线程负责“执行任务”。**

CPU 调度器相当于领导安排：

```text
员工 A：你先干这个
员工 B：你去干那个
员工 C：你暂时等一下
```

它调度的是“员工”，不是“办公室”。

# 5. 那线程自己有没有资源？

有。

所以面试的时候不要说：

> ❌ 线程没有自己的资源。

线程也需要保存自己执行所必需的信息。

比如同一个进程：

```text
进程
├── 线程 A
├── 线程 B
└── 线程 C
```

它们通常共享：

```text
代码段
数据段
堆
打开的文件
地址空间
```

但每个线程有自己独立的：

```text
栈
程序计数器 PC
寄存器状态
线程 ID
```

尤其是**栈**非常重要。

例如：

```java
void test() {
    int a = 10;
}
```

线程 A 调用 `test()`，线程 B 也调用 `test()`，它们不能共用同一个调用栈，否则函数调用现场就乱套了。

所以你可以形成一个非常重要的面试知识框架：

```text
                 进程
                  │
       ┌──────────┴──────────┐
       │                     │
   共享的资源             多个线程
       │
   地址空间            ┌────┼────┐
   代码段              A    B    C
   数据段              │    │    │
   堆                 栈   栈   栈
   文件                PC   PC   PC
   ...
```

# 6. 面试官问的时候怎么回答？

如果面试官问：

> 为什么说进程是资源分配的基本单位，线程是 CPU 调度的基本单位？

你可以回答：

> 操作系统通常以进程为单位管理和隔离资源，每个进程拥有独立的虚拟地址空间以及文件等资源；同一进程中的多个线程共享进程的大部分资源。
>
> 但是实际执行代码的是线程。操作系统的调度器会从可运行线程中选择线程分配到 CPU 上执行，因此线程是 CPU 调度的基本单位。每个线程又拥有自己的栈、程序计数器和寄存器上下文等执行现场。

这已经是一个比较标准的面试回答。

## 7. 你尤其要区分这两个问题

以后看到：

**资源分配**

脑子里想到：

```text
“东西归谁？”

→ 进程
```

看到：

**CPU 调度**

脑子里想到：

```text
“CPU 接下来让谁执行？”

→ 线程
```

所以最简单的记忆方式就是：

> **进程管资源，线程管执行。**
