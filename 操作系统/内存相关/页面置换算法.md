# 页面置换算法

## 1. 什么是页面置换？

在虚拟内存系统中，进程访问的页面并不一定全部位于物理内存中。

当进程访问某个页面时，如果该页面当前不在物理内存，就会发生**缺页异常（Page Fault）**。

如果此时物理内存还有空闲页框：

```text
缺页
 ↓
找到空闲页框
 ↓
将需要的页面调入内存
```

但如果物理内存已经满了：

```text
物理内存：

┌──────────┐
│ Page A   │
├──────────┤
│ Page B   │
├──────────┤
│ Page C   │
└──────────┘

现在需要 Page D
```

就必须选择一个已有页面移出/替换：

```text
Page A
Page B     → 选择一个淘汰
Page C

然后把 Page D 放进来
```

因此：

> **页面置换算法解决的问题就是：当物理内存不足时，应该淘汰哪个页面。**

一个好的页面置换算法应该尽可能：

> **降低缺页率（Page Fault Rate）。**

---

# 2. 常见页面置换算法

面试中最常见的有：

1. OPT：最佳页面置换算法
2. FIFO：先进先出算法
3. LRU：最近最少使用算法
4. Clock：时钟/第二次机会算法
5. LFU：最不经常使用算法

其中最重要的是：

```text
OPT
FIFO
LRU
Clock
```

---

# 3. OPT 最佳页面置换算法

## 3.1 基本思想

OPT（Optimal Page Replacement）：

> **淘汰未来最长时间不会被访问的页面。**

例如当前内存：

```text
A B C
```

未来的访问顺序：

```text
B → D → C → B → A
```

分析：

```text
A：很久以后才访问
B：马上访问
C：稍后访问
```

因此应该淘汰：

```text
A
```

因为 A 在未来最晚才会被访问。

---

## 3.2 优缺点

优点：

> 理论上可以获得最低的缺页率，是理想情况下的最优算法。

缺点：

> 实际系统无法准确知道程序未来会访问哪些页面。

所以 OPT 通常不能真正实现。

它最大的意义是：

> **作为理论最优值，用于衡量其他页面置换算法的性能。**

---

# 4. FIFO 先进先出算法

FIFO：

> **谁最早进入内存，就优先淘汰谁。**

例如内存有 3 个页框：

```text
进入顺序：

A → B → C
```

此时：

```text
┌───┐
│ A │ ← 最早进入
├───┤
│ B │
├───┤
│ C │ ← 最晚进入
└───┘
```

现在需要加载：

```text
D
```

FIFO 会淘汰：

```text
A
```

变成：

```text
B C D
```

下一次需要替换：

```text
B
```

因此它本质上可以使用**队列**实现：

```text
队头                  队尾
 ↓                     ↓

A → B → C

淘汰 A
      ↓

B → C → D
```

---

## 4.1 FIFO 的优点

实现非常简单。

只需要记录：

> 页面进入物理内存的先后顺序。

---

## 4.2 FIFO 的缺点

FIFO 最大的问题是：

> **最早进入内存的页面，不代表它以后不会经常使用。**

例如：

```text
A 是一个非常热门的页面
```

虽然 CPU 一直访问 A，但因为 A 最早进入内存，FIFO 还是可能把它淘汰。

所以 FIFO 没有考虑页面的实际访问情况。

---

# 5. Belady 异常

FIFO 有一个非常著名的问题：

**Belady's Anomaly（Belady 异常）**

正常直觉认为：

> 给程序更多物理页框，缺页次数应该减少。

但 FIFO 在某些情况下：

> **增加页框数量，反而可能导致缺页次数增加。**

这就是 Belady 异常。

例如经典页面访问序列：

```text
1 2 3 4 1 2 5 1 2 3 4 5
```

使用 FIFO：

```text
3 个页框 → 9 次缺页
4 个页框 → 10 次缺页
```

页框增加：

```text
3 → 4
```

缺页反而：

```text
9 → 10
```

这就是：

> **Belady 异常。**

面试中经常直接问：

> 哪种页面置换算法可能出现 Belady 异常？

回答：

> **FIFO。**

---

# 6. LRU 最近最少使用算法

LRU：

**Least Recently Used**

核心思想：

> **淘汰最长时间没有被访问过的页面。**

它和 OPT 非常容易混淆。

OPT 看的是：

```text
未来
```

LRU 看的是：

```text
过去
```

例如：

```text
最近访问：

A → B → C → A → B
```

现在内存：

```text
A B C
```

其中：

```text
B：刚刚访问
A：最近访问
C：已经很久没有访问
```

那么：

```text
淘汰 C
```

---

# 7. 为什么 LRU 比较合理？

程序访问内存通常具有**局部性原理（Locality）**。

主要包括：

### 时间局部性

如果一个数据刚刚被访问：

> 它在不久之后很可能再次被访问。

例如循环：

```java
for (...) {
    sum += nums[i];
}
```

某些代码和变量会被反复使用。

---

### 空间局部性

如果某个地址被访问：

> 它附近的地址很可能也会很快被访问。

例如遍历数组：

```text
nums[0]
nums[1]
nums[2]
nums[3]
...
```

地址通常是连续的。

---

因此 LRU 的逻辑是：

> 一个页面已经很久没有被访问，那么它未来短时间内被访问的概率可能相对较低。

所以把它淘汰。

---

# 8. LRU 怎么实现？

这是面试中非常高频的问题。

如果要求实现一个 LRU Cache，经典数据结构是：

```text
HashMap + 双向链表
```

HashMap：

```text
key → Node
```

用于：

> O(1) 找到某个节点。

双向链表：

```text
最近使用                        最久未使用
   ↓                              ↓

HEAD ⇄ A ⇄ B ⇄ C ⇄ D ⇄ TAIL
```

每次访问一个页面：

```text
访问 C

HEAD ⇄ C ⇄ A ⇄ B ⇄ D ⇄ TAIL
```

把它移动到最前面。

需要淘汰时：

```text
淘汰尾部 D
```

因此：

```text
查询：O(1)
更新：O(1)
删除：O(1)
```

这也是 LeetCode 146 LRU Cache 的核心思想。

---

# 9. LRU 的缺点

真正严格实现 LRU，需要持续记录页面访问顺序。

如果每次内存访问都要维护：

```text
谁刚刚访问
谁最久没有访问
```

成本会比较高。

因此：

> 实际操作系统通常不会简单地使用一个软件层面的“完美 LRU”来记录每次内存访问。

实际系统往往采用近似 LRU 的方法。

其中非常经典的就是：

**Clock 算法。**

---

# 10. Clock 时钟页面置换算法

Clock 也叫：

> **Second Chance Algorithm（第二次机会算法）**

它可以理解成：

> **对 LRU 的一种近似实现。**

---

## 10.1 基本思想

给每个页面维护一个：

```text
访问位 / Reference Bit
```

例如：

```text
Page A    R=1
Page B    R=0
Page C    R=1
Page D    R=1
```

`R = 1`：

```text
最近被访问过
```

`R = 0`：

```text
最近没有被访问
```

把页面组织成一个环：

```text
        A(1)
       /    \
    D(1)    B(0)
       \    /
        C(1)
```

再维护一个类似时钟指针的东西。

---

## 10.2 如何淘汰？

指针扫描页面。

如果：

```text
R = 0
```

说明最近没使用：

```text
直接淘汰
```

如果：

```text
R = 1
```

说明最近使用过：

```text
不淘汰
↓
把 R 修改成 0
↓
继续向后扫描
```

所以它叫：

> **第二次机会。**

例如：

```text
A(1)
```

本来轮到 A。

但是：

```text
R = 1
```

说明 A 最近被访问过。

于是：

```text
A(1) → A(0)
```

暂时放过 A。

继续检查 B：

```text
B(0)
```

发现：

```text
R = 0
```

于是：

```text
淘汰 B
```

---

# 11. 为什么 Clock 可以近似 LRU？

LRU 想知道：

> 谁最长时间没被访问？

但是精确记录这个信息成本比较高。

Clock 换了一种更便宜的方法：

```text
最近访问过？
     ↓
   R = 1

最近没观察到访问？
     ↓
   R = 0
```

虽然不能精确知道：

```text
A 已经 10 秒没访问
B 已经 20 秒没访问
```

但可以粗略区分：

```text
最近使用过
vs
最近没使用
```

所以：

> Clock 用较低的实现成本近似 LRU。

---

# 12. LFU 最不经常使用算法

LFU：

**Least Frequently Used**

核心思想：

> **淘汰访问次数最少的页面。**

例如：

```text
A → 访问 100 次
B → 访问 20 次
C → 访问 2 次
```

需要淘汰时：

```text
淘汰 C
```

因为：

```text
C 的访问频率最低
```

---

## LFU 和 LRU 的区别

LRU 看：

```text
多久没有访问
```

LFU 看：

```text
总共/一段时间内访问了多少次
```

例如：

```text
页面 A：

以前访问了 10000 次
但最近很久没访问
```

LRU 可能认为：

```text
应该淘汰 A
```

但简单 LFU 可能认为：

```text
A 访问次数这么高
不能淘汰
```

所以 LFU 也存在历史访问频率对当前判断产生干扰的问题，实际实现中常配合衰减等机制。

---

# 13. 几种算法对比

| 算法 | 淘汰谁 | 优点 | 缺点 |
|---|---|---|---|
| OPT | 未来最久不访问 | 理论最优 | 无法预知未来 |
| FIFO | 最早进入内存 | 实现简单 | 不考虑访问情况 |
| LRU | 最近最久没访问 | 符合局部性原理 | 精确实现成本较高 |
| Clock | 近期未被访问的页面 | 成本较低、近似 LRU | 不如精确 LRU |
| LFU | 访问频率最低 | 考虑访问频率 | 容易受历史访问影响 |

---

# 14. OPT、LRU、FIFO 最容易混淆的地方

可以这样记：

```text
             看什么？

OPT  ─────→ 看未来
            ↓
       未来最晚使用


LRU  ─────→ 看过去
            ↓
       过去最久没使用


FIFO ─────→ 看进入时间
            ↓
       最早进入内存
```

例如：

```text
OPT：
“未来谁最久用不到，我踢谁。”


LRU：
“过去谁最久没用，我踢谁。”


FIFO：
“谁最早来的，我踢谁。”


Clock：
“最近用过？再给你一次机会。”
```

# 15. 页面置换和缺页异常的完整关系

把前面的虚拟内存知识串起来：

```text
CPU 访问虚拟地址
        │
        ▼
       MMU
        │
        ▼
     TLB / 页表
        │
        ▼
页面当前能正常访问？
      /      \
    是        否
    │          │
正常访问    Page Fault
               │
               ▼
        操作系统处理缺页
               │
               ▼
         有空闲页框吗？
           /       \
         有         没有
         │           │
         │      页面置换算法
         │           │
         │      选择牺牲页面
         │           │
         └─────┬─────┘
               ▼
        准备目标物理页框
               │
               ▼
         调入需要的页面
               │
               ▼
           更新页表
               │
               ▼
         恢复程序执行
```

注意：

如果被淘汰的页面被修改过（Dirty Page），通常还需要先把修改后的内容写回对应的后备存储；如果页面没有被修改，则在有可靠后备副本的情况下通常可以直接丢弃。

# 面试重点

## Q1：什么是页面置换算法？

当发生缺页，并且没有足够的空闲物理页框时，操作系统需要选择一个当前驻留内存的页面作为牺牲页，以便腾出页框。

决定淘汰哪个页面的策略就是**页面置换算法**。

其主要目标是：

> **尽可能降低缺页率和页面换入换出的开销。**

---

## Q2：常见页面置换算法有哪些？

常见算法包括：

- OPT：淘汰未来最长时间不会访问的页面。
- FIFO：淘汰最早进入内存的页面。
- LRU：淘汰最近最长时间没有访问的页面。
- Clock：通过访问位给最近访问过的页面第二次机会，是一种经典的近似 LRU 思路。
- LFU：淘汰访问频率最低的页面。

---

## Q3：OPT 为什么不能实际实现？

因为 OPT 需要知道：

> 页面未来的访问顺序。

实际操作系统无法准确预知程序未来会访问哪些页面。

因此 OPT 主要用于理论分析和性能比较。

---

## Q4：LRU 为什么有效？

因为程序的内存访问通常具有**局部性原理**。

一个页面如果最近被访问过，那么短时间内再次访问它的概率往往较高。

因此 LRU 选择淘汰：

> 最近最长时间没有被访问的页面。

---

## Q5：为什么实际系统不一定实现严格 LRU？

因为严格 LRU 需要精确记录页面的访问先后顺序。

内存访问频率极高，如果每次访问都进行复杂的软件维护，会带来很大的性能开销。

因此实际系统通常利用硬件提供的访问相关信息，并采用近似 LRU 的页面回收策略。

Clock 就是经典的近似思想之一。

---

## Q6：什么是 Belady 异常？

Belady 异常是指：

> **增加物理页框数量后，缺页次数反而增加。**

FIFO 可能出现 Belady 异常。

而 OPT、LRU 属于栈算法，不会出现 Belady 异常。

---

# 最终速记

```text
页面置换算法
│
├── OPT
│    └── 淘汰“未来最久不用”
│        → 理论最优，但无法预知未来
│
├── FIFO
│    └── 淘汰“最早进入”
│        → 简单
│        → 可能出现 Belady 异常
│
├── LRU
│    └── 淘汰“过去最久没用”
│        → 符合局部性
│        → 精确实现成本较高
│
├── Clock
│    └── 看访问位
│        → 最近访问过就给第二次机会
│        → 经典近似 LRU 思想
│
└── LFU
     └── 淘汰“访问频率最低”
         → 可能受到历史访问频率影响
```

## 一句话记忆

> **OPT 看未来，LRU 看过去，FIFO 看谁先来，LFU 看谁用得少，Clock 看最近有没有用过。**
